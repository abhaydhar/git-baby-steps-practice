# Status Report Instructions

## Purpose

Use this document to complete the status report template in `template.md`. Keep the report concise, factual, and easy for stakeholders to review.

## Required Workflow

1. Open `template.md` and copy its structure into a new report.
2. Replace every bracketed placeholder with project-specific information.
3. Update the status, progress, deliverables, milestones, risks, and next steps.
4. Add evidence links, command output, or validation results where completion is claimed.
5. Record the date the report was last updated.
6. Review the report for unsupported claims before sharing it.

## Field Guidance

### Project Information

- Use the project name and reporting period that apply to the current update.
- Select one status: **On track**, **At risk**, **Delayed**, or **Complete**.
- Use the owner or team responsible for the report.
- Set the last-updated date to the date the report was finalized.

### Executive Summary

Summarize the project in 2–4 sentences. State the overall status, major progress, and any material risks or blockers.

### Progress

- Report completed work, current work, and planned work separately.
- Use percentages only when the underlying count or completion evidence is available.
- Do not claim work is complete without supporting evidence.

### Deliverables

- Use the owner, status, due date, and evidence for every deliverable.
- Use **Not started**, **In progress**, **Complete**, or **Blocked** as the status values.
- Add a link or note for the evidence supporting each completed deliverable.

### Milestones

- Enter the planned target date and actual completion date when available.
- Use **Planned**, **Complete**, or **Delayed** as the status values.
- Add notes for changes, dependencies, or delays.

### Risks and Issues

- Describe each risk or issue precisely.
- State its impact, mitigation, owner, and due date.
- Keep unresolved risks visible until a mitigation or resolution is documented.

### Next Steps

List actions in execution order. Include an owner and due date when the action has an accountable person.

### Evidence and Validation

- Add links, screenshots, command output, test results, or review notes.
- Record validation results accurately and do not infer success from an unrun check.

### Notes

Use this section for assumptions, dependencies, external decisions, or follow-up actions that do not fit elsewhere.

## Completion Checklist

- [ ] All bracketed placeholders were replaced.
- [ ] Project status is current.
- [ ] Progress is supported by evidence.
- [ ] Every deliverable has an owner and status.
- [ ] Every risk has an owner and mitigation.
- [ ] Next steps are actionable.
- [ ] The report includes a last-updated date.
- [ ] No unsupported completion claims were added.
